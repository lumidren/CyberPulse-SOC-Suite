# SOC-RULE-023: Script Host Running a Script from a User-Writable Path

> Generated by `python scripts/rule_docs.py` from the rule and the test evidence.

**Level** high · **ATT&CK** T1059.005, T1059.007 · **Version** 1.0.0 · `rules/sigma/win_script_host_user_writable.yml` · [Runbook](../runbooks/SOC-RULE-023.md)

## What it detects

Detects wscript.exe or cscript.exe executing .js, .jse, .vbs, .vbe or .wsf files from Downloads, Temp, AppData or Public folders, typical of malicious attachments and droppers.

## How it works

- `selection_img`: `Image` ends with one of `\wscript.exe`, `\cscript.exe`
- `selection_path`: `CommandLine` contains one of `\Downloads\`, `\AppData\`, `\Temp\`, `\Users\Public\`
- `selection_ext`: `CommandLine` contains one of `.js`, `.jse`, `.vbs`, `.vbe`, `.wsf`
- condition: `all of selection_*`

## Telemetry it needs

Sysmon Event 1 (process creation) / Security 4688 with command line (logsource `windows/process_creation`). If that source is not collected, the rule cannot fire: see [DATA_SOURCES.md](../coverage/DATA_SOURCES.md).
