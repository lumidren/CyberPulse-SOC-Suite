# SOC-RULE-054: DNS Query with an Unusually Long Label (possible tunnelling)

> Generated by `python scripts/rule_docs.py` from the rule and the test evidence.

**Level** medium · **ATT&CK** T1071.004 · **Version** 1.0.0 · `rules/sigma/net_zeek_dns_long_label.yml` · [Runbook](../runbooks/SOC-RULE-054.md)

## What it detects

A DNS name containing a label of 40 or more characters made only of letters, digits and hyphens, or a TXT lookup of a name with a 30+ character label. Encoded data in DNS names looks like this; ordinary host names rarely do.

## How it works

- `selection_long`: `query` matches regex `(^|\.)[A-Za-z0-9-]{40,}\.`
- `selection_txt`: `qtype_name` equals `TXT` AND `query` matches regex `(^|\.)[A-Za-z0-9-]{30,}\.`
- condition: `1 of selection_*`

## Telemetry it needs

Zeek dns.log (network sensor) (logsource `zeek/dns`). If that source is not collected, the rule cannot fire: see [DATA_SOURCES.md](../coverage/DATA_SOURCES.md).

## Tuning

- Expected false positive: DKIM and domain-verification TXT records with long tokens
- Expected false positive: Some CDNs and anti-virus cloud lookups encode hashes in names
- Prefer an expiring exception for one known-benign pattern; change the logic (with a version bump) only when it is wrong for everyone. See [TUNING.md](../TUNING.md).
