# SOC-RULE-050: Phishing Email Reported by a User or Failing DMARC with a Link or Attachment

> Generated by `python scripts/rule_docs.py` from the rule and the test evidence.

**Level** high · **ATT&CK** T1566.001, T1566.002 · **Version** 1.0.0 · `rules/sigma/email_phishing_reported_or_auth_fail.yml` · [Runbook](../runbooks/SOC-RULE-050.md)

## What it detects

A delivered message that a recipient reported as phishing, or that failed DMARC and carries a link or attachment. Message metadata only (Microsoft 365 EmailEvents style); no bodies.

## How it works

- `selection_delivered`: `DeliveryAction` equals `Delivered`
- `selection_reported`: `ReportedByUser` equals `True`
- `selection_dmarc_fail`: `AuthenticationResults` contains `dmarc=fail`
- `selection_link`: `Urls` is present
- `selection_attachment`: `AttachmentSha256` is present
- condition: `selection_delivered and (selection_reported or (selection_dmarc_fail and (selection_link or selection_attachment)))`

## Telemetry it needs

Microsoft 365 email events (message trace / Defender for Office) (logsource `m365/email`). If that source is not collected, the rule cannot fire: see [DATA_SOURCES.md](../coverage/DATA_SOURCES.md).

## Evidence it works (synthetic data only)

- Samples in `rules/tests/`: 2 positive, 3 negative
- Scripted attack generator: no
- Matches on the 600-event benign baseline before exceptions: 0

## Tuning

- Expected false positive: Newsletters and SaaS senders with broken DMARC alignment
- Expected false positive: Users reporting legitimate but unexpected mail
- Prefer an expiring exception for one known-benign pattern; change the logic (with a version bump) only when it is wrong for everyone. See [TUNING.md](../TUNING.md).
