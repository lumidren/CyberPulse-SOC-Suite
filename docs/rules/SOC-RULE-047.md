# SOC-RULE-047: Access to a Canary File

> Generated by `python scripts/rule_docs.py` from the rule and the test evidence.

**Level** high · **ATT&CK** T1005, T1083 · **Version** 1.0.0 · `rules/sigma/win_honey_file_access.yml` · [Runbook](../runbooks/SOC-RULE-047.md)

## What it detects

Object-access audit (Event 4663) on a decoy file planted where an intruder looks for credentials or finance data. Needs a SACL on the decoy files (docs/CANARIES.md).

## How it works

- `selection`: `EventID` equals `4663` AND `ObjectName` ends with one of `\Passwords_2019.xlsx`, `\vpn_credentials.txt`, `\Payroll_Q4_FINAL.xlsx`
- `filter_backup`: `ProcessName` ends with one of `\MsMpEng.exe`, `\wbengine.exe`
- condition: `selection and not filter_backup`

## Telemetry it needs

Windows Security log (Advanced Audit Policy) (logsource `windows/security`). If that source is not collected, the rule cannot fire: see [DATA_SOURCES.md](../coverage/DATA_SOURCES.md).

## Evidence it works (synthetic data only)

- Samples in `rules/tests/`: 1 positive, 2 negative
- Scripted attack generator: no
- Matches on the 600-event benign baseline before exceptions: 0
- Quality score: 90/100 ([QUALITY.md](../coverage/QUALITY.md))

## Tuning

- Expected false positive: Backup or AV software not in the filter reading every file
- Expected false positive: Users opening the decoy out of curiosity (that is still worth a conversation)
- Prefer an expiring exception for one known-benign pattern; change the logic (with a version bump) only when it is wrong for everyone. See [TUNING.md](../TUNING.md).
