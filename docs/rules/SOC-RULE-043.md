# SOC-RULE-043: Brute Force From One Source Against One Account (raw 4625 correlation)

> Generated by `python scripts/rule_docs.py` from the rule and the test evidence.

**Level** high · **ATT&CK** T1110.001 · **Version** 1.0.0 · `rules/sigma/correlations/win_brute_force_raw_logons.yml` · [Runbook](../runbooks/SOC-RULE-043.md)

## What it detects

Ten or more failed network/RDP logons for the same account from the same source IP within five minutes. Works on raw, unaggregated Security events, unlike SOC-RULE-002 which needs a collector-side count.

## How it works

A **event_count** correlation: within 300 s, grouped by `IpAddress`, `TargetUserName`, it fires when the number of events is at least 10. One burst raises one alert. Base rules:

`failed_network_logon` (Failed Network or RDP Logon (base rule)):

- `selection`: `EventID` equals `4625` AND `LogonType` equals one of `3`, `10`
- `aggregated`: `FailedAttemptsCount` equals `None`
- condition: `selection and aggregated`

## Telemetry it needs

Windows Security log (Advanced Audit Policy) (logsource `windows/security`). If that source is not collected, the rule cannot fire: see [DATA_SOURCES.md](../coverage/DATA_SOURCES.md).

## Evidence it works (synthetic data only)

- Sequence tests: `tests/test_sigma_correlation.py`, `tests/test_threshold_tuning.py`
- Scripted attack generator: no

## Tuning

- Expected false positive: A service or scheduled task retrying with an expired password (same source, same account).
- Prefer an expiring exception for one known-benign pattern; change the logic (with a version bump) only when it is wrong for everyone. See [TUNING.md](../TUNING.md).
