# SOC-RULE-003: Suspicious Scheduled Task Creation for Persistence

> Generated by `python scripts/rule_docs.py` from the rule and the test evidence.

**Level** high · **ATT&CK** T1053.005 · **Version** 1.0.1 · `rules/sigma/win_scheduled_task_persistence.yml` · [Runbook](../runbooks/SOC-RULE-003.md)

## What it detects

Detects creation of a new Windows Scheduled Task containing suspicious script interpreters or web download strings.

## How it works

- `selection`: `EventID` equals `4698`
- `keywords`: `TaskContent` contains one of `powershell`, `cmd.exe`, `http:`, `https:`, `wscript`, `cscript`
- condition: `selection and keywords`

## Telemetry it needs

Windows Security log (Advanced Audit Policy) (logsource `windows/security`). If that source is not collected, the rule cannot fire: see [DATA_SOURCES.md](../coverage/DATA_SOURCES.md).

## Evidence it works (synthetic data only)

- Samples in `rules/tests/`: 1 positive, 1 negative

- Matches on the 600-event benign baseline before exceptions: 19

## Tuning

- Expected false positive: Legitimate software installers creating scheduled update tasks with network installers.
- Prefer an expiring exception for one known-benign pattern; change the logic (with a version bump) only when it is wrong for everyone. See [TUNING.md](../TUNING.md).
