# SOC-RULE-045: Mass File Write by One Process (ransomware encryption or mass rename)

> Generated by `python scripts/rule_docs.py` from the rule and the test evidence.

**Level** critical · **ATT&CK** T1486 · **Version** 1.0.0 · `rules/sigma/correlations/win_mass_file_write.yml` · [Runbook](../runbooks/SOC-RULE-045.md)

## What it detects

One process on one host creates or overwrites 100+ files in user or share paths within one minute, the pattern of ransomware writing encrypted copies. Sysmon has no rename event, so in-place renames are only seen when the new name is written as a file create; complete rename coverage needs Windows object-access auditing (Event 4663).

## How it works

A **event_count** correlation: within 60 s, grouped by `Computer`, `Image`, it fires when the number of events is at least 100. One burst raises one alert. Base rules:

`user_path_file_create` (File Created in a User or Share Path (base rule)):

- `selection`: `TargetFilename` contains one of `\Users\`, `\Shares\`
- `filter_known_writers`: `Image` ends with one of `\MsMpEng.exe`, `\SearchProtocolHost.exe`, `\OneDrive.exe`, `\TiWorker.exe`, `\robocopy.exe`
- condition: `selection and not filter_known_writers`

## Telemetry it needs

Sysmon Event 11 (file create) (logsource `windows/file_event`). If that source is not collected, the rule cannot fire: see [DATA_SOURCES.md](../coverage/DATA_SOURCES.md).
