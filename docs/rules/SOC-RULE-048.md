# SOC-RULE-048: AWS Canary Credential Used

> Generated by `python scripts/rule_docs.py` from the rule and the test evidence.

**Level** critical · **ATT&CK** T1552.001 · **Version** 1.0.0 · `rules/sigma/cloud_aws_canary_credential_use.yml` · [Runbook](../runbooks/SOC-RULE-048.md)

## What it detects

Any CloudTrail call by the IAM user that owns a planted canary access key. The key has no permissions and is left in files an intruder would loot (config backups, scripts), so any call means the file was stolen.

## How it works

- `selection`: `userIdentity.userName` equals one of `canary-backup-reader`, `canary-ci-deployer`
- condition: `selection`

## Telemetry it needs

AWS CloudTrail (management events) (logsource `aws/cloudtrail`). If that source is not collected, the rule cannot fire: see [DATA_SOURCES.md](../coverage/DATA_SOURCES.md).
