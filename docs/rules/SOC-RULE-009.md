# SOC-RULE-009: Suspicious AWS STS AssumeRole Abuse Across External Account

> Generated by `python scripts/rule_docs.py` from the rule and the test evidence.

**Level** high · **ATT&CK** T1548, T1078.004 · **Version** 1.0.1 · `rules/sigma/cloud_aws_assumerole_abuse.yml` · [Runbook](../runbooks/SOC-RULE-009.md)

## What it detects

Detects suspicious AWS STS AssumeRole calls originating from unapproved foreign IPs or anomalous role ARNs, characteristic of cloud privilege escalation and cross-account lateral movement.

## How it works

- `selection`: `eventName` equals `AssumeRole` AND `eventSource` equals `sts.amazonaws.com`
- `suspicious_arn`: `requestParameters.roleArn` contains one of `OrganizationAccountAccessRole`, `AdministratorAccess`, `SecurityAudit`
- `filter`: `sourceIPAddress` starts with one of `10.`, `172.16.`, `192.168.`
- condition: `selection and suspicious_arn and not filter`

## Telemetry it needs

AWS CloudTrail (management events) (logsource `aws/cloudtrail`). If that source is not collected, the rule cannot fire: see [DATA_SOURCES.md](../coverage/DATA_SOURCES.md).
