# SOC-RULE-052: Executable Downloaded over HTTP by a Script Client or to a Raw IP

> Generated by `python scripts/rule_docs.py` from the rule and the test evidence.

**Level** high · **ATT&CK** T1105 · **Version** 1.0.0 · `rules/sigma/net_zeek_http_executable_from_script_client.yml` · [Runbook](../runbooks/SOC-RULE-052.md)

## What it detects

Zeek saw a Windows executable (MIME application/x-dosexec) fetched over plain HTTP by a scripting or LOLBin user agent, or straight from an IP address instead of a host name.

## How it works

- `selection_exe`: `resp_mime_types` contains `application/x-dosexec`
- `selection_ua`: `user_agent` contains one of `WindowsPowerShell`, `Microsoft-CryptoAPI`, `BITS`, `curl`, `Wget`
- `selection_raw_ip`: `host` matches regex `^[0-9]{1,3}(\.[0-9]{1,3}){3}(:[0-9]+)?$`
- condition: `selection_exe and (selection_ua or selection_raw_ip)`

## Telemetry it needs

Zeek http.log (network sensor) (logsource `zeek/http`). If that source is not collected, the rule cannot fire: see [DATA_SOURCES.md](../coverage/DATA_SOURCES.md).

## Tuning

- Expected false positive: Software updaters that download installers over HTTP from IP-addressed mirrors
- Expected false positive: Admin scripts pulling tools from an internal web server by IP
- Prefer an expiring exception for one known-benign pattern; change the logic (with a version bump) only when it is wrong for everyone. See [TUNING.md](../TUNING.md).
