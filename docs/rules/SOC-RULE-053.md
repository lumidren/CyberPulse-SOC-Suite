# SOC-RULE-053: Many Unique Subdomains of One Domain from One Host (DNS tunnelling)

> Generated by `python scripts/rule_docs.py` from the rule and the test evidence.

**Level** high · **ATT&CK** T1071.004 · **Version** 1.0.0 · `rules/sigma/correlations/net_dns_tunnel_unique_subdomains.yml` · [Runbook](../runbooks/SOC-RULE-053.md)

## What it detects

One source asks for 50 or more different subdomains of the same parent domain within five minutes, the shape of data being encoded into DNS names (iodine, dnscat2, DNS C2). Content-delivery and telemetry domains can do the same; allowlist them with an exception.

## How it works

A **value_count** correlation: within 300 s, grouped by `IpAddress`, `query_parent`, it fires when the number of distinct values of `query` is at least 50. One burst raises one alert. Base rules:

`dns_query_any` (DNS Query to Any Domain (base rule)):

- `selection`: `query_parent` is present
- `filter_reverse`: `query_parent` ends with one of `in-addr.arpa`, `ip6.arpa`
- condition: `selection and not filter_reverse`

## Telemetry it needs

Zeek dns.log (network sensor) (logsource `zeek/dns`). If that source is not collected, the rule cannot fire: see [DATA_SOURCES.md](../coverage/DATA_SOURCES.md).

## Tuning

- Expected false positive: CDNs and anti-virus or telemetry services that use per-request subdomains
- Expected false positive: DNS-based service discovery in some enterprise software
- Prefer an expiring exception for one known-benign pattern; change the logic (with a version bump) only when it is wrong for everyone. See [TUNING.md](../TUNING.md).
