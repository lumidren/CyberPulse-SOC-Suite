# SOC-RULE-006: Rapid File Encryption and Ransomware Canary Modification

> Generated by `python scripts/rule_docs.py` from the rule and the test evidence.

**Level** critical · **ATT&CK** T1486 · **Version** 1.0.1 · `rules/sigma/win_ransomware_canary.yml` · [Runbook](../runbooks/SOC-RULE-006.md)

## What it detects

Detects suspicious mass file creation with known ransomware extension patterns (.locked, .encrypted, HOW_TO_DECRYPT) targeting canary decoy directories.

## How it works

- `selection`: `TargetFilename` ends with one of `.locked`, `.encrypted`, `.crypted`, `HOW_TO_DECRYPT.txt`, `README_RESTORE.txt`
- condition: `selection`

## Telemetry it needs

Sysmon Event 11 (file create) (logsource `windows/file_event`). If that source is not collected, the rule cannot fire: see [DATA_SOURCES.md](../coverage/DATA_SOURCES.md).

## Evidence it works (synthetic data only)

- Samples in `rules/tests/`: 2 positive, 1 negative
- Scripted attack generator: yes
- Matches on the 600-event benign baseline before exceptions: 0
- Quality score: 100/100 ([QUALITY.md](../coverage/QUALITY.md))

## Tuning

- Expected false positive: Legitimate encryption software (e.g. VeraCrypt, 7-Zip encrypting explicit archives).
- Prefer an expiring exception for one known-benign pattern; change the logic (with a version bump) only when it is wrong for everyone. See [TUNING.md](../TUNING.md).
