## What fired

Detects attempts to impair host defenses by disabling Windows Defender real-time monitoring and script scanning via Set-MpPreference or registry modification.

- Severity: **CRITICAL** · ATT&CK: T1562.001
- Rule file: `rules/sigma/win_defender_tamper.yml` · Data source: Sysmon Event 1 (process creation) / Security 4688 with command line

## Triage

Playbook: `default-triage`.

1. Confirm the alert against the raw telemetry in the incident record
2. Check whether the host, user or source IP appears in other open incidents
3. Decide true or false positive and record why in the analyst notes
4. If false positive, propose a rule exception (rules/exceptions.yml) with an owner and expiry

Fields to check in the event: `CommandLine`, `Image`.

## Response

- Proposed action: `REVERT_DEFENDER_POLICY_AND_ISOLATE` (TIER_2_HOST, always needs approval, rollback PARTIAL).
- What it does: Restores Defender real-time protection settings and isolates the host.
- How it can go wrong: A legitimate admin change is reverted; isolation of a critical host; a GPO reapplies the attacker's setting after the revert.
- Before approving: collect or check the volatile evidence package on the incident; confirm the target is not a protected asset or account.

## Known false positives

- Rare administrative maintenance scripts during isolated software deployment.

## Escalate when

- The activity continues after containment, or appears on a second host or account.
- A protected asset, privileged account or production service is involved.
- You cannot rule out real attacker activity within the playbook's steps.
