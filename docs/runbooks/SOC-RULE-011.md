# Runbook: SOC-RULE-011 Vulnerable Signed Driver Load (BYOVD Evasion)

> Generated by `python scripts/rule_docs.py` from the rule, its playbook and the containment
> catalogue. Edit those sources, not this page.

## What fired

Detects loading of known vulnerable signed drivers (e.g., gdrv.sys, mhyprot2.sys) commonly leveraged in Bring Your Own Vulnerable Driver (BYOVD) attacks to disable endpoint security agents from kernel-mode.

- Severity: **CRITICAL** · ATT&CK: T1068
- Rule file: `rules/sigma/win_driver_byovd_load.yml` · Data source: Sysmon (driver load, Event 6)

## Triage

Playbook: `default-triage`.

1. Confirm the alert against the raw telemetry in the incident record
2. Check whether the host, user or source IP appears in other open incidents
3. Decide true or false positive and record why in the analyst notes
4. If false positive, propose a rule exception (rules/exceptions.yml) with an owner and expiry

Fields to check in the event: `EventID`, `ImageLoaded`, `SignatureStatus`, `Signed`.

## Response

- Proposed action: `UNLOAD_DRIVER_AND_ENFORCE_WDAC_BLOCK` (TIER_2_HOST, always needs approval, rollback PARTIAL).
- What it does: Unloads a vulnerable driver and adds it to the WDAC block policy.
- How it can go wrong: Blocking a driver that hardware needs (storage, network) can leave the host unbootable or offline.
- Before approving: collect or check the volatile evidence package on the incident; confirm the target is not a protected asset or account.

## Known false positives

- Legitimate legacy hardware utility drivers installed prior to WDAC enforcement

## Escalate when

- The activity continues after containment, or appears on a second host or account.
- A protected asset, privileged account or production service is involved.
- You cannot rule out real attacker activity within the playbook's steps.
