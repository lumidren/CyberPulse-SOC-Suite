# Runbook: SOC-RULE-030 Windows Firewall Disabled via netsh or PowerShell

> Generated by `python scripts/rule_docs.py` from the rule, its playbook and the containment
> catalogue. Edit those sources, not this page.

## What fired

Detects the host firewall being turned off for all profiles with netsh advfirewall or Set-NetFirewallProfile -Enabled False.

- Severity: **HIGH** · ATT&CK: T1562.004
- Rule file: `rules/sigma/win_firewall_disabled.yml` · Data source: Sysmon Event 1 (process creation) / Security 4688 with command line

## Triage

Playbook: `default-triage`.

1. Confirm the alert against the raw telemetry in the incident record
2. Check whether the host, user or source IP appears in other open incidents
3. Decide true or false positive and record why in the analyst notes
4. If false positive, propose a rule exception (rules/exceptions.yml) with an owner and expiry

Fields to check in the event: `CommandLine`, `Image`.

## Response

- No containment is proposed (`ENRICH_AND_ALERT_ANALYST`): alert and investigate. If you decide to act, propose an action on the incident (`POST /api/incidents/<id>/propose`); it still needs approval.

## Known false positives

- Troubleshooting by network administrators on isolated test hosts

## Escalate when

- The activity continues after containment, or appears on a second host or account.
- A protected asset, privileged account or production service is involved.
- You cannot rule out real attacker activity within the playbook's steps.
