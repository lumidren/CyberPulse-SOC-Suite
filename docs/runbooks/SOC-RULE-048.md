# Runbook: SOC-RULE-048 AWS Canary Credential Used

> Generated by `python scripts/rule_docs.py` from the rule, its playbook and the containment
> catalogue. Edit those sources, not this page.

## What fired

Any CloudTrail call by the IAM user that owns a planted canary access key. The key has no permissions and is left in files an intruder would loot (config backups, scripts), so any call means the file was stolen.

- Severity: **CRITICAL** · ATT&CK: T1552.001
- Rule file: `rules/sigma/cloud_aws_canary_credential_use.yml` · Data source: AWS CloudTrail (management events)

## Triage

Playbook: `deception-hit`.

1. Treat as a likely intrusion; decoys have no legitimate use
2. Check the announced decoy test calendar before escalating
3. Trace the source host or IP and open a scoped investigation

Fields to check in the event: `userIdentity.userName`.

## Response

- No containment is proposed (`ENRICH_AND_ALERT_ANALYST`): alert and investigate. If you decide to act, propose an action on the incident (`POST /api/incidents/<id>/propose`); it still needs approval.

## Known false positives

- Your own periodic test of the canary (record the test window)

## Escalate when

- The activity continues after containment, or appears on a second host or account.
- A protected asset, privileged account or production service is involved.
- You cannot rule out real attacker activity within the playbook's steps.

Open an appeal on the incident ([APPEALS.md](../APPEALS.md)) and tune it ([TUNING.md](../TUNING.md)).
