# Runbook: SOC-RULE-012 Pass-the-Hash Logon Patterns (NTLM and seclogo)

> Generated by `python scripts/rule_docs.py` from the rule, its playbook and the containment

## What fired

Detects logon events typical of pass-the-hash: a LogonType 9 (NewCredentials) logon via the seclogo process with the Negotiate package, as produced by tools that inject an NTLM hash into a new logon session, or a network NTLM logon with a zero session key length.

- Severity: **HIGH** · ATT&CK: T1550.002
- Rule file: `rules/sigma/win_pass_the_hash.yml` · Data source: Windows Security log (Advanced Audit Policy)

## Triage

Playbook: `credential-theft`.

1. Identify the process and account that accessed the credential material
2. Collect the volatile evidence package before approving any isolation
3. List accounts with sessions on the host; plan password resets for exposed accounts
4. Check domain controllers for follow-on use (4624 logon type 3/9, 4769 from the same source)

Fields to check in the event: `AuthenticationPackageName`, `EventID`, `KeyLength`, `LogonProcessName`, `LogonType`, `TargetUserName`.

## Response

- No containment is proposed (`ENRICH_AND_ALERT_ANALYST`): alert and investigate. If you decide to act, propose an action on the incident (`POST /api/incidents/<id>/propose`); it still needs approval.

## Known false positives

- runas /netonly by administrators (LogonType 9 via seclogo)
- Legacy NTLM-only applications and network scanners

## Escalate when

- The activity continues after containment, or appears on a second host or account.
- A protected asset, privileged account or production service is involved.
- You cannot rule out real attacker activity within the playbook's steps.
