# Runbook: SOC-RULE-020 Backup Catalog Deletion or Boot Recovery Disabled

> Generated by `python scripts/rule_docs.py` from the rule, its playbook and the containment
> catalogue. Edit those sources, not this page.

## What fired

Detects deletion of the Windows backup catalog (wbadmin delete catalog) or disabling of boot recovery (bcdedit recoveryenabled no / ignoreallfailures), typical ransomware preparation.

- Severity: **CRITICAL** · ATT&CK: T1490
- Rule file: `rules/sigma/win_ransomware_recovery_inhibition.yml` · Data source: Sysmon Event 1 (process creation) / Security 4688 with command line

## Triage

Playbook: `ransomware`.

1. Page the incident lead immediately; ransomware is time-critical
2. Confirm scope - which shares and hosts show encrypted files or deleted shadow copies
3. Approve or reject the proposed isolation within minutes, not hours
4. Verify backups are offline and intact before any restore

Fields to check in the event: `CommandLine`, `Image`.

## Response

- No containment is proposed (`ENRICH_AND_ALERT_ANALYST`): alert and investigate. If you decide to act, propose an action on the incident (`POST /api/incidents/<id>/propose`); it still needs approval.

## Known false positives

- Deliberate decommissioning of a server's local backups by administrators

## Escalate when

- The activity continues after containment, or appears on a second host or account.
- A protected asset, privileged account or production service is involved.
- You cannot rule out real attacker activity within the playbook's steps.
