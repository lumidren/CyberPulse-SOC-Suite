# Runbook: SOC-RULE-042 Entra ID Admin Consent Granted to an Application

## What fired

Detects tenant-wide admin consent being granted to an application in Entra ID audit logs, a path to persistent OAuth access (illicit consent grant).

- Severity: **MEDIUM** · ATT&CK: T1528
- Rule file: `rules/sigma/cloud_entra_admin_consent.yml` · Data source: Entra ID audit logs

## Triage

Playbook: `cloud-identity`.

1. Confirm the sign-in or API call with the user or workload owner out of band
2. Review the identity's other activity in the same window (CloudTrail / Entra audit logs)
3. If confirmed, revoke sessions and rotate credentials; record the scope of access

Fields to check in the event: `ConsentType`, `OperationName`.

## Response

- No containment is proposed (`ENRICH_AND_ALERT_ANALYST`): alert and investigate. If you decide to act, propose an action on the incident (`POST /api/incidents/<id>/propose`); it still needs approval.

## Known false positives

- Approved onboarding of a new SaaS application by a cloud administrator

## Escalate when

- The activity continues after containment, or appears on a second host or account.
- A protected asset, privileged account or production service is involved.
- You cannot rule out real attacker activity within the playbook's steps.
