# Runbook: SOC-RULE-031 SAM or SYSTEM Registry Hive Saved to Disk

> Generated by `python scripts/rule_docs.py` from the rule, its playbook and the containment
> catalogue. Edit those sources, not this page.

## What fired

Detects reg.exe saving the SAM, SECURITY or SYSTEM hive (reg save), which lets an attacker extract local password hashes offline.

- Severity: **CRITICAL** · ATT&CK: T1003.002
- Rule file: `rules/sigma/win_sam_hive_export.yml` · Data source: Sysmon Event 1 (process creation) / Security 4688 with command line

## Triage

Playbook: `credential-theft`.

1. Identify the process and account that accessed the credential material
2. Collect the volatile evidence package before approving any isolation
3. List accounts with sessions on the host; plan password resets for exposed accounts
4. Check domain controllers for follow-on use (4624 logon type 3/9, 4769 from the same source)

Fields to check in the event: `CommandLine`, `Image`.

## Response

- Proposed action: `ISOLATE_HOST_AND_KILL_PROCESS` (TIER_2_HOST, always needs approval, rollback PARTIAL).
- What it does: Network-isolates a host (WinRM) and terminates the offending process.
- How it can go wrong: Isolating a server stops a business service; killing the wrong PID; isolation succeeds but the kill fails (or the reverse); the host is unreachable so nothing happens while the record says it ran.
- Before approving: collect or check the volatile evidence package on the incident; confirm the target is not a protected asset or account.

## Known false positives

- Forensic collection by incident responders (expected during an investigation)

## Escalate when

- The activity continues after containment, or appears on a second host or account.
- A protected asset, privileged account or production service is involved.
- You cannot rule out real attacker activity within the playbook's steps.
