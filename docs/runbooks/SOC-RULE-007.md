# Runbook: SOC-RULE-007 Kerberoasting TGS Ticket Request with RC4 Encryption

## What fired

Detects suspicious Kerberos Service Ticket (TGS) requests with RC4-HMAC (0x17) encryption targeting Service Principal Names (SPNs), characteristic of Kerberoasting attacks.

- Severity: **HIGH** · ATT&CK: T1558.003
- Rule file: `rules/sigma/win_kerberoasting.yml` · Data source: Windows Security log (Advanced Audit Policy)

## Triage

Playbook: `credential-theft`.

1. Identify the process and account that accessed the credential material
2. Collect the volatile evidence package before approving any isolation
3. List accounts with sessions on the host; plan password resets for exposed accounts
4. Check domain controllers for follow-on use (4624 logon type 3/9, 4769 from the same source)

Fields to check in the event: `EventID`, `ServiceName`, `TicketEncryptionType`, `TicketOptions`.

## Response

- Proposed action: `RESET_SERVICE_ACCOUNT_AND_REVOKE_KERBEROS_TICKET` (TIER_3_IDENTITY, always needs approval, rollback PARTIAL).
- What it does: Forces a password reset on a service account and purges its Kerberos tickets.
- How it can go wrong: Every service using that account fails until its stored credential is updated.
- Before approving: collect or check the volatile evidence package on the incident; confirm the target is not a protected asset or account.

## Known false positives

- Legacy applications requiring RC4 encryption for Kerberos authentication

## Escalate when

- The activity continues after containment, or appears on a second host or account.
- A protected asset, privileged account or production service is involved.
- You cannot rule out real attacker activity within the playbook's steps.
