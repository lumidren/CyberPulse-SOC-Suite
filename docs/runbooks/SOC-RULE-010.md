## What fired

Detects impossible travel login anomalies in Microsoft Entra ID (Azure AD) where user authentications originate from geographically disparate IP addresses within an unrealistic physical travel window.

- Severity: **HIGH** · ATT&CK: T1078
- Rule file: `rules/sigma/cloud_entra_impossible_travel.yml` · Data source: Entra ID sign-in logs

## Triage

Playbook: `cloud-identity`.

1. Confirm the sign-in or API call with the user or workload owner out of band
2. Review the identity's other activity in the same window (CloudTrail / Entra audit logs)
3. If confirmed, revoke sessions and rotate credentials; record the scope of access

Fields to check in the event: `Category`, `OperationName`, `ResultType`, `RiskEventTypes`, `RiskLevelDuringSignIn`.

## Response

- Proposed action: `REVOKE_ENTRA_REFRESH_TOKENS_AND_FORCE_MFA` (TIER_3_IDENTITY, always needs approval, rollback PARTIAL).
- What it does: Revokes Entra ID sessions and adds the account to an MFA step-up group (live only when configured).
- How it can go wrong: The user is signed out everywhere; if the Conditional Access policy is misconfigured, step-up never triggers or locks the user out; the Graph call fails midway (flagged for manual follow-up).
- Before approving: collect or check the volatile evidence package on the incident; confirm the target is not a protected asset or account.

## Known false positives

- Corporate VPN exit node transitions with split tunneling

## Escalate when

- The activity continues after containment, or appears on a second host or account.
- A protected asset, privileged account or production service is involved.
- You cannot rule out real attacker activity within the playbook's steps.
